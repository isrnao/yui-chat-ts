## 2. Oracle（原作をローカルで動かした参照環境）

macOS の Perl 5.34 で原作がそのまま動く。変更は `jcode.pl` の 1 行だけ必要だった（`do convf(*_);` は Perl 5.20 で
廃止された構文なので `&convf(*_);` にする）。

```bash
# 例: 入室（REQUEST_METHOD / CONTENT_LENGTH / REMOTE_ADDR / HTTP_USER_AGENT を渡す）
env -i REQUEST_METHOD=POST CONTENT_LENGTH=58 SCRIPT_NAME=/2shot.cgi REMOTE_ADDR=127.0.0.1 HTTP_USER_AGENT=UA-A \
  perl 2shot.cgi <<< 'action=entry&chat_name=alice&sex=M&room=01&cookie=1&mes=hello' | iconv -f CP932 -t UTF-8
```

Oracle は受け入れ確認で「正解の HTML と見た目」を得るために使う（design.md「テスト戦略」）。リポジトリの外に置く。

## 3. 画面の構成（v5.0.1）

原作はフレーム（`<frameset>`）で上下 2 画面に分かれ、フォームの送信先（`target`）でどちらの画面を書き換えるかが決まる。

| 画面（原作の action）   | 置かれる場所                               | 内容                                                                                      |
| ----------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------- |
| 入口（`First`）         | ページ全体                                 | `rows="30%,70%"`、`border=5`、`bordercolor=#555555`。上 = 入室フォーム、下 = 空室状況     |
| 入室フォーム（`Form`）  | 入口の上                                   | 中央寄せ・幅 70% の表の中に見出しとフォーム。送信先は `_parent`（ページ全体が入れ替わる） |
| 空室状況（`List`）      | 入口の下                                   | 更新の切り替えリンク、部屋の一覧表、「ホームページへ戻る」、著作表示の画像                |
| 入室後（`InForm`）      | ページ全体                                 | `rows="20%,80%"`、同じ境界線。上 = 入力画面、下 = ログ画面                                |
| 入力画面（`ChatForm`）  | 入室後の上                                 | 部屋名と自分の名前、更新・閉鎖・退室のボタン、発言欄、自動更新の選択、注意書き 2 行       |
| ログ画面（`Chat`）      | 入室後の下                                 | 新しい順のログ、画面クリア（管制者）、更新方式・無発言監視タイマ・表示行数の表示          |
| お知らせ画面（`error`） | 送信元の `target` による（下の画面が多い） | 見出し 1 つと箇条書き。最後に「空室状況へ」「ホームページへ戻る」「直前の画面」           |

### 3.1 入室フォーム

| 要素         | 内容                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| 見出し       | `<h1>ツーショットチャット</h1>`                                                              |
| チャット名   | `チャット名 ` + テキスト（`size=30`、`maxlength=30`）                                        |
| 性別         | `性別` + ラジオ 3 つ: 男（`#5555ff`）/ 女（`#ff0000`）/ ？（`#555555`）。保存値がなければ ？ |
| 部屋         | セレクト。先頭 `▼ルームを選択してください`（値は空）、続けて ルーム１〜ルーム１０            |
| ボタン       | `入室`、`開設`（`name=Make`）                                                                |
| 保存         | 小さい文字（`<font size=-1>`）でチェックボックス（既定でオン）+ `保存`                       |
| プロフィール | `プロフィール ` + テキスト（`size=50`、`maxlength=60`）                                      |
| フォーカス   | 保存されたチャット名がなければチャット名、あればプロフィール                                 |

要素の区切りは `<br>`。性別と部屋・ボタン・保存は同じ行、プロフィールは次の行。

### 3.2 空室状況

- 先頭に空行（`<p><br>`）。中央寄せ・幅 70% の表の中に置く
- 更新の切り替え: 手動のときは `〔`**`手動更新`**`〕〔自動更新(60秒)にする〕`、自動のときは
  `〔60秒自動更新中〕〔手動更新にする〕`（`〔〕` の中がリンク）。自動のときは 60 秒ごとに再読み込み
- 表: `border=3 cellpadding=2 cellspacing=2 width=100%`。見出し行は黒地（`#000000`）に白字（`#FFFFFF`）で
  `ルーム名 / 状態 / 性別 / チャット名 / プロフィール`
- 各行: ルーム名は `<th nowrap>`。状態・性別は中央寄せ・折り返しなし。値の前後に `&nbsp;` が入る

| 状態   | 表示            | 性別・チャット名・プロフィール |
| ------ | --------------- | ------------------------------ |
| 空室   | `#8888ff`       | 空                             |
| 待機中 | 太字、`#cc6633` | 管制者のもの                   |
| 満室   | `#ff0000`       | 空                             |

- 表の後に `〔ホームページへ戻る〕`、右寄せで著作表示の画像（GIF、43×35、`alt="2SHOT-CHAT v5.0.1 製作/著作"`、
  CGI-RESCUE へのリンク）

### 3.3 入力画面

- 表: `border=5 cellpadding=2 cellspacing=2`
- 1 行目: `<strong>《ルーム名》　</strong>` + 自分の名前 + `(性別)`（性別は色付き）、`いつでも手動更新` ボタン、
  管制者なら `閉鎖` と `相手を退室`、入室者なら `退室`（2 列ぶん）。`閉鎖` と `退室` のボタンの文字は、前後に
  半角の空白が 1 つずつ入っている（`value=" 閉鎖 "`。ボタンの幅が変わる）
- 2 行目: 発言欄（`size=60`、`maxlength` なし）+ `発言` ボタン、`&nbsp;`**`自動更新`** + ラジオ
  `なし`（既定）/ `自動(20秒)` / `自動(30秒)`
- 表の後に小さい文字で 2 行:
  - `※ブラウザの更新(リロード)ボタンは使わないでください。`
  - `※時間差により管制者(開設者)になりたい人が入室者として同時にルームに入ってしまう場合があります。`
- 確認ダイアログ（`confirm`）: 閉鎖 = `閉鎖します. よろしいですか？`、相手を退室 = `相手を退室させます. よろしいですか？`、
  退室 = `あなただけ退室します. よろしいですか？`
- 発言を送ると、0.5 秒後に発言欄の文字を**残したまま全選択**してフォーカスする（消さない）
- `いつでも手動更新` とラジオのクリックは、発言欄を空にして同じフォームを送る（= その時点の自動更新の設定で更新）
- `相手を退室` を押すと自動更新を `なし` に戻す

### 3.4 ログ画面

- 行は新しい順。1 行ごとに `<hr>` で区切る
  - 自分の発言: `名前 > 発言` を `#888888` で、続けて小さい文字で `(HH:MM)`（同じ色）
  - それ以外: **名前** + ` > 発言` + 小さい文字で `(HH:MM)`。「おしらせ」の行もこの形（名前が太字）
- 最後にフォーム: 管制者なら `画面クリア` ボタン、続けて `〔手動更新〕` または `〔N秒自動更新〕`、
  `〔無発言監視タイマX秒経過→300秒後閉鎖〕`、`〔表示10行〕`
- X は表示した時点の「最後の発言からの経過秒数」。表示中には進まない
- 自動更新のときは N 秒ごとに再読み込み

### 3.5 お知らせ画面

```
<h1>見出し</h1>
<ul>
  <li>本文 1
  <li>本文 2 …
  <p>
  <li>〔空室状況へ〕（太字のリンク。ページ全体を入口に戻す）
  <p>
  <li>〔ホームページへ戻る〕
  <p>
  <li>〔直前の画面〕（history.back）
</ul>
```

### 3.6 全体の見た目

- 本文: 背景 `#FFFFFF`、文字 `#000000`、未訪問リンク `link=#f5555`、訪問済み `vlink=#ff5555`
- `#f5555` は 5 桁で不正な色。HTML の「レガシーな色の解析」で `f55550` → `#f55550` になる（O8）
- フォントや文字の大きさは指定がなく、ブラウザの既定。`<font size=-1>` は一段小さい文字

## 5. データと状態遷移

部屋ごとに 3 つのファイルを持つ。

| ファイル | 1 行目                                                     | 2 行目以降                                                                  |
| -------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| `ent`    | 最終発言時刻（空 = 空室）                                  | 入室者ごとの認証コードのハッシュ（`crypt`）。0 番目が管制者、1 番目が入室者 |
| `mes`    | 管制者: 名前・性別・プロフィール・ホスト・UA（タブ区切り） | 入室者の同じ項目                                                            |
| `log`    | `HH:MM` `名前` `発言`（タブ区切り、古い順）                |                                                                             |

```
空室 ──入室/開設──▶ 待機中（管制者のみ） ──入室/開設──▶ 満室（ロック）
  ▲                    │   ▲                               │
  │                    │   └──── 退室（入室者）/ 相手を退室 ─┘
  └── 閉鎖 / 300 秒無発言 / ログが 5000 バイト超 / 重複入室 ──┘
```

- 管制者が抜ける手段は「閉鎖」だけ。窓を閉じただけなら、300 秒後に誰かが画面を開いた時点で空室に戻る
- 最終発言時刻は、発言と入室のときだけ更新する。更新（再読み込み）では変わらない（O14）
- 満室の部屋へ入ろうとすると、何も表示せずに入口へ戻る

### 5.1 入室の規則

1. 最終発言から 300 秒以上たっていれば、先に部屋を空室に戻す
2. すでに 2 人いれば入口へ戻す
3. チャット名が空、または `,` `;` `:` を含むなら `匿名` にする（匿名扱いのお知らせを出す）。`<` `>` は先に
   `&lt;` `&gt;` へ置き換わって `;` を含むので、これらを含む名前も `匿名` になる（N5 の文言が `<>` を挙げている理由）
4. 管制者がいる状態で、名前が `匿名` なら `匿名2` に、管制者と同じ名前なら `匿名` にする（どちらも匿名扱いのお知らせを出す）
5. 空室なら、ログなどの残りを消してから入る（前の会話は残らない）
6. 管制者と**ホスト名と UA が同じ**人が入室者として入ろうとしたら、部屋を空室に戻してエラーにする（重複入室）
7. 1 人目は管制者、2 人目は入室者になる。「開設」は、空室なら「入室」と同じ。管制者がいるときに押すと、入室者として
   入ったうえで警告のお知らせを出す
8. お知らせを書き込み、最終発言時刻を今にする

### 5.2 お知らせの文言

名前の欄は `おしらせ`（N10 だけ `管制者へおしらせ`）。`{性別}` は色付きの表記。原作ではホスト名の HTML コメントが
`さん` と `が` の間に入り、空白が 2 つ続く（表示では 1 つに詰まる）。

| #   | きっかけ                     | 文言                                                                                                         |
| --- | ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| N1  | 管制者の入室                 | `{名前}({性別})さん が管制者(ルームを開設した方)として入室しました.`                                         |
| N2  | 入室者の入室                 | `{名前}({性別})さん が入室しましたので、このチャットルームをロックしました.`                                 |
| N3  | 管制者がいるときの開設       | `{名前}({性別})さん がは開設しようとしましたが、管制者がいる状態で入室しました（管制者と相談してください）.` |
| N4  | プロフィールがある入室       | `{名前}さんのプロフィール『 {プロフィール} 』`                                                               |
| N5  | 匿名扱い                     | `チャット名が入力されていないか、使えない文字<>,;:が検知された等の理由で匿名扱いとなります.`                 |
| N6  | 入室者の退室                 | `{名前}さんが退室しましたので待機中になります.`                                                              |
| N7  | 相手がいないときの相手を退室 | `現在、退室させる相手はいません.`                                                                            |
| N8  | 相手を退室                   | `相手を退室させましたので待機中になります.`                                                                  |
| N9  | 画面クリア                   | `管制者(最初に入室した方)によって画面がクリアされました.`（ログはこの 1 行だけになる）                       |
| N10 | 管制者以外が閉鎖しようとした | `参加者の操作に不正な手順を検知しました.`                                                                    |

入室時の書き込み順は N1〜N3 のどれか → N4 → N5。ログは新しい順に出るので、画面では N5 が一番上になる。

### 5.3 お知らせ画面の文言

| #   | 見出し          | 本文                                                                                                        | 原作で出る場面                                 |
| --- | --------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| E1  | エラー          | 部屋を選択してください.                                                                                     | 部屋を選ばずに入室                             |
| E2  | エラー          | 重複入室を検知しましたので、一旦空室にしました. / 空室状況を確認してください.                               | 5.1 の 6                                       |
| E3  | 終了1           | あなたは現在の利用者であるという認証ができません. / または、データが制限サイズを越えましたので閉鎖しました. | 認証コードなしでログ画面を開いた               |
| E4  | 終了            | このチャットは終了しました.                                                                                 | 閉鎖・退室させられた・時間切れ・容量超過のあと |
| E5  | 終了            | あなたは現在の利用者であるという認証ができません.                                                           | 認証コードなしで退室                           |
| E6  | 終了            | 既にこのチャットから退室しています.                                                                         | 退室済みで退室                                 |
| E7  | 退室            | ご利用ありがとうございました.                                                                               | 入室者の退室                                   |
| E8  | 閉鎖            | ご利用ありがとうございました.                                                                               | 管制者の閉鎖                                   |
| E9  | エラー          | あなたは現在の管理者であるという認証ができませんでした.                                                     | 管制者以外の閉鎖                               |
| E10 | エラー          | 認証コードの発行に失敗しました. / 空室状況へ入りなおしてください.                                           | `crypt` の失敗（再実装では起きない）           |
| E11 | 異常 / 異常終了 | （なし）/ 入り口から入り直してください.                                                                     | 不明な操作                                     |
| E12 | システムエラー  | チャットファイルが開けません. など                                                                          | データファイルの読み書きの失敗                 |

下の画面だけが入れ替わり、上の入力画面はそのまま残る。

## 6. 実行・コードの確認で分かった原作の不具合と癖

| #   | 内容                                                                                                                                                                                                                        | 確認方法                                                                             |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| O1  | **管制者に「画面クリア」ボタンが出ない。** 入室処理の途中で人数の変数が空文字に戻り、管制者の `num` が `""` になる。ログ画面は `num eq '0'` で判定するので一致しない（入力画面は数値比較なので閉鎖・相手を退室は出る）      | Oracle で入室し、ログ画面に `画面クリア` がないことを確認                            |
| O2  | **認証なしの 1 リクエストで部屋が閉鎖される。** `?action=Chat&room=04`（認証コードなし）で、ログ画面は E3 を出す前に部屋を空室に戻す。v4.2 の「部外者によるいたずら閉鎖防止」は直っていない。`Clear` も認証の前に実行される | Oracle で `ent` が 25 → 0 バイトになり、一覧が空室になった（`Clear` はコードで確認） |
| O3  | **認証コードが予測できる。** `srand(time\|$$)` で 8 文字を作る。1 回目の実行では、入室者に管制者と同じコードが発行された（`num=0` を付ければ入室者が管制者として操作できる）                                                | Oracle で 2 人を続けて入室させて確認                                                 |
| O4  | 一覧の表示（GET）が、時間切れの部屋を空室に戻す書き込みをする                                                                                                                                                               | コードで確認                                                                         |
| O5  | ログの行数の上限は、発言のときに 1 行ずつ捨てて守る。入室直後はお知らせが最大 3 行増えるので、一時的に 10 行を超える                                                                                                        | コードで確認                                                                         |
| O6  | 入室者の入室お知らせの HTML コメントには、入室者ではなく管制者のホスト名が入る（画面には出ない）                                                                                                                            | Oracle で `<!-- localhost -->` を確認                                                |
| O7  | 管制者がいるときの「開設」のお知らせは「さん がは開設しようとしましたが」と助詞が重なる                                                                                                                                     | Oracle で確認                                                                        |
| O8  | 未訪問リンクの色が 5 桁の `#f5555`。ブラウザは `#f55550` として描く                                                                                                                                                         | HTML の仕様で確認（実装時に Oracle の描画で確かめる）                                |
| O9  | `jcode.pl` は Perl 5.20 以降でそのままでは動かない                                                                                                                                                                          | Oracle で確認                                                                        |
